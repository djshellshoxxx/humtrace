# HumTrace research foundations: books, journals, and archived sources

**Research date:** 2026-10-08  
**Purpose:** Give later design and implementation work a traceable reading list across DSP, spectral estimation, acoustics, forensic audio, evidence handling, and web/archive research. These are research leads and engineering foundations, not a claim that HumTrace is a validated forensic method or a substitute for a qualified examiner. Publisher abstracts, library catalogs, university repositories, standards bodies, DOI records, and archive documentation were preferred. Book contents are summarized; no copyrighted book passages are reproduced.

## Decisions this research supports

1. **Separate measurements from interpretation.** Show measured signal properties (frequency, level, bandwidth, spectral prominence, duration, drift, reverberation descriptors, channel relationships) separately from a proposed environmental explanation. A narrowband tone, reverberant signature, or learned similarity score does not by itself establish a device, cause, room, geographic location, or edit. Forensic audio is a combination of signal processing, acoustics, evidence handling, and interpretation, not a single classifier. [1–4]
2. **Make every result reproducible.** Record input identity/hash, decoder and version, channels, sample rate, any transformations, algorithm/version, parameters, timebase, warnings, and output hash. Preserve original bytes and analyze a working copy. [1, 3, 5]
3. **Use long-window spectral measurements for frequency resolution, short windows for time localization, and expose that tradeoff.** Frame length determines the time/frequency compromise; a denser-looking zero-padded plot is not added physical resolving power. Keep units and normalization explicit, and validate with known signals and difficult negatives. [6–9]
4. **Treat the interface as an examination notebook.** It should show the full recording and selected regions, per-channel views, parameter provenance, comparison context, annotations, and a clear distinction between original evidence and derived views. The report should include limitations and an audit-friendly processing history. This is a product-design inference from the forensic handling/reporting sources, not a UI prescription mandated by a standard. [1, 3–5]
5. **Treat archive captures as dated representations with incomplete provenance.** A Wayback capture is useful to recover a version of a page or find an old technical source, but a replay may be incomplete, recomposed, or not byte-identical to the original server response. An archive's timestamp and checksum help identify and check a stored object; they do not independently prove who authored or originally published it. [10–15]

## Peer-reviewed literature and standards most relevant to HumTrace

### Forensic practice, evidence, interpretation

- **Maher, R. C. (2009). “Audio forensic examination: authenticity, enhancement, and interpretation.” _IEEE Signal Processing Magazine_, 26(2), 84–94. DOI: [10.1109/MSP.2008.931080](https://doi.org/10.1109/MSP.2008.931080).** Author's Montana State University [publication record](https://www.cnhp.montana.edu/rmaher/publications/index.html), accessed 2026-10-08. A foundational overview joining signal processing with forensic questions and interpretation. Use for the product's vocabulary and the need to distinguish a measured property from an examiner's conclusion. It is a 2009 overview, not a validation report for the current product. [17]
- **SWGDE, _Best Practices for Forensic Audio_, v2.5 (2022-06-09).** [SWGDE audio publications index](https://www.swgde.org/documents/published-by-committee/audio/) and [document PDF](https://www.swgde.org/wp-content/uploads/2023/11/2022-06-09-SWGDE-Best-Practices-for-Forensic-Audio_v2.5.pdf), accessed 2026-10-08. Covers examination workflow, handling, and documentation. The committee index also lists later audio publications; always confirm the current revision before relying on a procedure. These are consensus best-practice documents, not a claim that any one jurisdiction adopts them as binding law. [3]
- **SWGDE, _Best Practices for Digital Audio Authentication_, v1.3 (2018-09-20).** [Current document page](https://www.swgde.org/documents/published-complete-listing/15-a-001-swgde-best-practices-for-digital-audio-authentication/), accessed 2026-10-08. Defines authentication as substantiating asserted provenance and describes measurement-based approaches such as MDCT compression-history assessment, with uncertainty dependent on compression algorithm and bitrate. Relevant as a boundary: HumTrace's environmental analysis is not a complete authentication method. [4]
- **SWGDE, _Best Practices for the Enhancement of Digital Audio_, v2.0 (2025-08-21).** [Current audio index](https://www.swgde.org/documents/published-by-committee/audio/) and [document page](https://www.swgde.org/documents/published-complete-listing/20-a-001-2/), accessed 2026-10-08. Calls for a working copy, ROI identification, technical assessment, a planned workflow, and awareness of unwanted artifacts. This supports immutable source handling, a non-destructive analysis path, recorded parameter choices, and warnings when a feature changes the signal. [5]
- **SWGDE, _Minimum Requirements for Testing Tools Used in Digital and Multimedia Forensics_ (2018; confirm revision at source).** [Document page](https://www.swgde.org/documents/published-complete-listing/18-q-001-minimum-requirements-for-testing-tools-used-in-digital-and-multimedia-forensics/), accessed 2026-10-08. Use it when defining tool-verification evidence: intended use, limitations, known test data, and empirical behavior must be documented. Do not imply that merely passing HumTrace's own tests constitutes external forensic validation. [18]

### ENF and environmental claims

- **Grigoras, C. (2005). “Digital audio recording analysis: the electric network frequency (ENF) criterion.” _International Journal of Speech, Language and the Law_, 12(1), 63–76. DOI: [10.1558/sll.2005.12.1.63](https://doi.org/10.1558/sll.2005.12.1.63).** This is a foundational paper describing ENF as a potentially useful signal for audio-recording analysis. Treat ENF extraction, timestamp matching, and claimed edit detection as a separate validated feature, not as an implication of simply observing 50/60 Hz tones. [19]
- **Grigoras, C. (2007). “Applications of ENF criterion in forensic audio, video, computer and telecommunication analysis.” _Forensic Science International_, 167(2–3), 136–145. DOI: [10.1016/j.forsciint.2006.06.033](https://doi.org/10.1016/j.forsciint.2006.06.033).** Publisher/abstract and PubMed record: [Elsevier](https://www.sciencedirect.com/science/article/pii/S0379073806004312), [PubMed](https://pubmed.ncbi.nlm.nih.gov/16884872/), accessed 2026-10-08. Use to characterize ENF's proposed forensic uses, while preserving the distinction between a candidate mains-related component and a justified ENF match. [20]
- **Hua, G. et al. (2024). “Factors affecting forensic electric network frequency matching – A comprehensive study.” _Digital Communications and Networks_, 10(4), 1121–1130. DOI: [10.1016/j.dcan.2023.01.009](https://doi.org/10.1016/j.dcan.2023.01.009).** [Publisher record](https://www.sciencedirect.com/science/article/pii/S2352864823000226), accessed 2026-10-08. Evaluates test/reference length, temporal resolution, and SNR; its abstract reports duration and SNR as consequential factors. Any HumTrace ENF matching feature must therefore include minimum-duration and SNR checks, use a suitable synchronized reference, and be validated with realistic distortions and false-match rates. [21]
- **Zhao, H., and H. Malik (2013). “Audio Recording Location Identification Using Acoustic Environment Signature.” _IEEE Transactions on Information Forensics and Security_, 8(11), 1746–1759. DOI: [10.1109/TIFS.2013.2278843](https://doi.org/10.1109/TIFS.2013.2278843).** This is a direct prior study of acoustic-environment features for location identification. Its experiments use a defined dataset of two speakers, eight environments, and four microphones, including microphone-independent and compression conditions. Those bounded conditions matter: they do not warrant a general “this arbitrary recording is from room X” output. Review the full paper and evaluation design before implementing comparable features. [22]
- **Delgado-Gutiérrez, G., F. Rodríguez-Santos, O. Jiménez-Ramírez, and R. Vázquez-Medina (2017). “Acoustic environment identification by Kullback–Leibler divergence.” _Forensic Science International_, 281, 134–140. DOI: [10.1016/j.forsciint.2017.10.031](https://doi.org/10.1016/j.forsciint.2017.10.031).** [Publisher record](https://www.sciencedirect.com/science/article/abs/pii/S0379073817304334), accessed 2026-10-08. The method compares a disputed recording with reference recordings from declared candidate places. This is a *closed-set comparison* question; HumTrace should only make a similar comparison claim when users supply suitable reference recordings and the method has been independently validated. [23]
- **Eaton, J., N. D. Gaubitch, A. H. Moore, and P. A. Naylor (2016). “Estimation of Room Acoustic Parameters: The ACE Challenge.” _IEEE/ACM Transactions on Audio, Speech, and Language Processing_, 24(10), 1681–1693. DOI: [10.1109/TASLP.2016.2577502](https://doi.org/10.1109/TASLP.2016.2577502).** [TU Delft repository record](https://research.tudelft.nl/en/publications/estimation-of-room-acoustic-parameters-the-ace-challenge/), accessed 2026-10-08. A challenge/evaluation perspective on estimating reverberation time and direct-to-reverberant ratio under realistic speech/audio conditions. Use benchmark discipline: define estimand, conditions, reference, metric, and test split before claiming accuracy. [24]

- **IEEE Transactions on Information Forensics and Security** for signal-based forensic research, including audio environment signatures. [22]

- **Journal of the Audio Engineering Society** and AES Audio Forensics conference proceedings for expert practice and technical papers. AES's official [audio-forensics resource page](https://aes.org/audio-topics/audio-forensics-2/) points to SWGDE and ASTM resources; its papers are useful primary material, but individual conference papers should not be described as journal articles. [25]

## Internet Archive, Wayback, and historical technical sources

### What the archive record means

- RFC 7089 describes a Memento as a prior state (representation) of an original resource at an archival datetime; it also explicitly cautions that the response body served for a memento may not be byte-for-byte identical to a response previously served by the live original resource. Cite the **original URL, archive URL, capture timestamp, and access date** separately. [10]
- The Internet Archive's CDX index identifies captures and exposes fields such as original URL, timestamp, MIME type, status, digest, and length. The CDX server's own documentation notes that capture results and scope depend on query/match mode and that indexes have limits. Save the exact CDX query or exact capture URL in research notes when source discovery depends on it. [11]
- The Library of Congress describes WARC as a record-based web-archive format whose records capture metadata such as date, type, and length; LOC identifies WARC as its preferred web-archive format. A WARC file preserves captured HTTP/web resources and metadata; it is not by itself a scholarly authentication of their claims. [12]
- Internet Archive's Metadata API returns item and file metadata; its examples include file size and checksum fields such as MD5 and CRC32. These values are useful for identifying/validating the downloaded object against the archive's recorded object, but checksums prove byte identity relative to the checked copy, not authorship or truth of the source. [13]
- Archived replay can omit dynamic or interaction-dependent content. Archive-It documents failures around JavaScript, interaction, and uncaptured linked resources. An apparent page rendering is therefore not proof that every script, embedded source, citation, or contemporaneous asset was captured. [14]
- More generally, a Memento may show different states for different URLs/resources. If a replay supplies linked CSS, images, scripts, or downloadable files from different capture dates, note that the rendered “page” may combine temporal states. Inspect the captured primary HTML, headers/metadata, and individual linked assets when that detail matters. [10, 11, 14]

### Research protocol for archived pages, technical textfiles, and transcripts

1. **Search for the authoritative source first.** Look for the author's university page/repository, journal/DOI landing page, publisher catalog, standards body, RFC, software repository/release, or institutional catalog. Use Wayback when the primary source has moved, disappeared, or a historical revision is itself relevant.
2. **Identify the resource precisely.** Record author/organization, title, original URL, publisher/repository, publication or revision date, archive capture timestamp, exact archived URL, access date, and—where available—CDX status/MIME type/digest/length. For an Internet Archive uploaded item, record the item identifier and exact filename, uploader/creator metadata as *asserted metadata*, media type/format, and file checksum.
3. **Check capture completeness.** Inspect the exact capture and linked assets; do not rely only on the calendar or a Wayback “closest” capture. For PDFs/text, compare title page, version/date, pagination, references, and cryptographic checksum with any publisher/institutional copy. For transcripts, compare with the original audio/video where possible and record transcript provider, version, timestamp conventions, and whether it is human-, machine-, or edited-transcribed. For OCR, treat extracted text as a discovery aid; verify quotations, numbers, equations, and tables against the image/PDF.
4. **Use primary-source triangulation.** An old textfile or transcript can reveal an earlier command/API behavior or provide a search lead. Confirm technical claims against the source code/version, standards text, official manual, or peer-reviewed article that owns the claim. Do not use archive upload metadata alone to establish an author, publication date, scientific review, or forensic validity.
5. **Preserve access details in the research note.** Include persistent DOI/repository citation first, then an “Archived copy” URL with capture date. If a live source changed since the capture, state which claims are supported by the historical version and why that version is needed. Do not silently quote a mutable replay as if it were the current page.
6. **Respect rights and reproducibility.** Store citations and short research summaries rather than republishing copyrighted books or journal chapters. If a research dataset or file is needed in tests, record rights/license, origin, checksum, transformations, and a stable version; prefer synthetic and explicitly rights-cleared validation material.

### Historical textfiles, mailing-list posts, and transcripts: quality hierarchy

1. **Best:** publisher/standards/institutional original or repository copy with a stable identifier and visible version metadata.
2. **Strong archival evidence for what was captured:** a dated WARC/Memento or IA item with a clear original URL/creator/version, capture metadata, downloadable original file, and recorded checksum; ideally corroborated by a second archive or independent citation.
3. **Useful discovery evidence:** an old mailing-list mirror, README, textfile collection, scanned book, cached conference transcript, personal site mirror, or user-uploaded IA item. Such items may preserve otherwise lost detail, but uploader-provided metadata, OCR, transcription, and date claims are not automatically verified.
4. **Do not use as sole support for a scientific claim:** unattributed copied snippets, unsourced transcripts, social posts, or archive search result text. Trace each claim back to an identifiable study, standard, text, or implementation version.

## HumTrace design and validation tasks implied by this reading

| Area | Specification/build implication | Evidence needed before making a strong claim |
|---|---|---|
| Evidence intake | Keep source bytes untouched; hash before/after; analyze derived copies; explain decoding, channel extraction, and transformations. | Fixtures with known file hashes, decoder behavior, malformed/truncated samples, and repeatable output. [3, 5] |
| Spectral display | Label FFT bins, interpolation, PSD vs amplitude spectrum, dBFS vs SPL, window, frame/hop, frequency and time resolution. Preserve per-channel views. | Analytic tone/noise tests across fractional bins, duration, SNR, windows, sample rates, nearby tones, and transformations. [6–9] |
| Environmental similarity | Present descriptor vectors and comparison conditions; distinguish within-recording recurrence, similarity to user-provided references, and known-room identification. Include “unknown/outside reference set.” | Multi-session, multi-device, varied source content, microphone positions, distances, occupancy, codec, gain, and adverse conditions; subject-disjoint or session-disjoint splits and false-match rates. [16, 22–24] |
| ENF | Keep nominal 50/60 Hz harmonic support as a candidate measurement; make ENF sequence extraction and reference matching a separate opt-in module. | Known-reference and negative recordings; minimum duration/SNR checks; synchronized trusted references; tested drift, resampling, filtering, codecs, and false-match rates. [19–21] |
| Claims and report language | Default to “consistent with / differs from / insufficient evidence” tied to measured features. Avoid physical source, exact location, edit, date, or authenticity conclusions without a validated method and appropriate reference data. | A claim-to-evidence table per detector, technical review, and review of report wording by forensic practitioners. [1, 3, 4, 17] |
| App provenance | Record app/build, algorithm and parameter version, selected region/timebase, source hash, run timestamp, warnings, and output hash in machine-readable reports. Make manual notes attributable and timestamped. | Deterministic regression runs, schema/version tests, integrity checks, and export/import round trips. [1, 3–5] |

## Reading order for upcoming implementation

1. Maher, _Principles of Forensic Audio Analysis_, especially evidence handling, authenticity assessment, and interpretation; Zjalic, _Digital Audio Forensics Fundamentals_, especially preparatory analysis, acoustics, and reporting. [1, 2]
2. MIT 6.341 spectral analysis / periodogram / STFT notes, then Oppenheim–Schafer or Smith for equations, scaling, and estimator assumptions. [7, 8]
3. Hayes for statistical spectral estimation and uncertainty once the prototype moves beyond simple peak heuristics. [9]
4. Kuttruff and the ACE Challenge for acoustic interpretation and evaluation design; room-identification studies for comparison tasks and their closed-set assumptions. [16, 22–24]
5. SWGDE current audio, authentication, enhancement, and tool-testing documents before implementing evidence-facing features or wording. [3–5, 18]
6. The ENF papers before designing any reference-matching or timestamp claim. [19–21]
